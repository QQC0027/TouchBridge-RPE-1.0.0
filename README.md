# TouchBridge → RPE（Windows 版）

把笔记本触控板当作打谱工具：用手指在触控板上做动作，程序生成 Phigros 格式的谱面，保存为 `.pez` 文件。这个文件可以在 Phigros / Phira 里游玩，也可以在 PhiEdit 里继续修改。

本工具只支持 Windows。所有处理都在本机完成，不需要账号，也不连接外部服务器。

> **项目来源**：本项目改编自 [MiGuo2787/TouchBridge-RPE](https://github.com/MiGuo2787/TouchBridge-RPE)，是其在 Windows 平台上的改编版本。原项目面向 Mac 触控板，本项目针对 Windows 精确式触控板重新实现了采集器与交互流程。

## 开始前需要准备什么

| 项目 | 说明 |
| --- | --- |
| 电脑系统 | Windows 10+，64 位 |
| 触控板 | 需要支持 Windows 的「精确式触控板」标准。多数笔记本内置触控板符合；老式触控板或某些外接设备可能不行 |
| Python | 3.10 或更高版本。启动脚本会检查，没有会提示安装 |
| .NET 8 SDK | 只在首次构建采集器程序时需要，同样由启动脚本检查 |
| 浏览器 | Edge、Chrome 或其他现代浏览器 |

Python 和 .NET 需要自行安装；启动脚本只负责检查、提示，并自动创建 Python 环境、安装依赖、构建采集器程序。

如何确认触控板符合要求：打开「设置 → 蓝牙和其他设备 → 触摸板」，如果能看到触摸板设置以及三指、四指手势选项，一般就符合。再打开设备管理器，看是否有「HID-compliant touch pad」或「精确式触摸板」。

## 第一次运行

1. 下载项目并解压。
2. 双击文件夹里的 `run.bat`。
3. 等待窗口执行完成。首次运行会创建 Python 环境、安装依赖并构建采集器，时间会久一些。
4. 浏览器会自动打开制谱页面，同时弹出采集器窗口。

项目里有四个主要部分：`run.bat` 是启动脚本，`TouchBridge` 是采集器程序，`backend` 负责生成谱面，`frontend` 是网页界面。日常使用只需要双击 `run.bat`。

## 认识采集器窗口

窗口右上角用一个圆点和一行文字表示当前状态：

- 绿色圆点、「正在发送」：触控板已找到，消息正常发往本机的谱面程序。
- 橙色圆点、「读不到触控板」：没有找到符合要求的触控板。
- 灰色圆点、「已暂停」：你点了「暂停发送」。

窗口左边是触控板的分区图，手指按下时会显示青色标记；右边五行对应最多五根手指，显示所在区域、状态和坐标；下方是最近发出的消息。

按钮的作用：

- 「暂停发送」/「恢复发送」：临时停止或继续向谱面程序发送消息。
- 「清空」：清掉当前所有手指状态。
- 「端口」输入框和「应用」按钮：两个本机程序之间通信用的号码，默认是 9000，通常不需要改动。

## 录制时的专注模式

点网页里的「开始录制」后，采集器会自动进入专注模式：

- 隐藏鼠标指针，并把它固定在当前位置，打谱时光标不会乱跑。
- 临时禁用触控板的三指/四指滑动与点按手势，避免被系统当成切换桌面、打开任务视图等操作。单指采集不受影响。
- 按 `ESC` 解除鼠标锁定（显示并允许移动鼠标），录制仍在进行，可以照常点击网页按钮。
- 按 `Alt+Enter` 重新隐藏并锁定鼠标，可反复切换。
- 点「停止录制」、关闭采集器窗口或程序异常退出时，鼠标与触控板手势会自动恢复到原来的设置。

采集器窗口顶部会显示当前是「鼠标已锁定」还是「鼠标已解除」。如果快捷键被其它软件占用，窗口底部消息区会给出提示，此时仍可通过「停止录制」正常恢复。

## 制作一份谱面

1. 在网页里导入音频，点播放，确认能听到声音。
2. 确认采集器窗口显示绿色状态。
3. 在网页里点「开始监听 OSC」，右下角能看到消息滚动。OSC 只是消息的格式名称，不需要额外设置。
4. 点「开始录制」，然后跟着音乐在触控板上做动作。
5. 动作和音符的对应关系：短按生成 Tap（蓝键），按住生成 Hold（长条），慢慢拖动生成 Drag（黄键），快速扫动生成 Flick（红键）。
6. 录制结束后点「停止录制」。
7. 填写谱面名称、作者和难度，点「导出」，得到 `.pez` 文件。

如果音符整体偏早或偏晚，点网页里的「自动校准」，或者手动调整「采样补偿」的设置。

## 检查是否正常

没有触控板也可以先检查消息能不能发出去。在命令行里进入项目目录，运行：

```bat
TouchBridge\dist\TouchBridge.exe --osctest
```

它会发出一批测试消息，并显示发送数量。再运行：

```bat
TouchBridge\dist\TouchBridge.exe --diagnose
```

它会检查触控板是否被找到，结果同时保存到 `%TEMP%\touchbridge-diagnose.txt`。这两个命令只是检查，不会影响正在运行的程序。

## 常见问题

**双击 `run.bat` 一闪而过，或者提示找不到 Python。**
安装 Python 3.10 或更高版本，安装时勾选「Add python.exe to PATH」，然后重新双击。

**提示缺少 .NET 8 SDK，或者构建失败。**
到 `https://dotnet.microsoft.com/download/dotnet/8.0` 安装 SDK（不是 Runtime），重新运行 `run.bat`。

**窗口显示「读不到触控板」。**
先确认「设置」里能打开触摸板选项，设备管理器里有触控板设备。老式 Synaptics / Elan 触控板和部分外接设备不支持。也可以运行 `--diagnose` 查看是否检测到设备。

**状态是绿色，但手指按上去没有反应。**
先点一下采集器窗口让它获得焦点，再试。如果仍然没有反应，运行 `--diagnose`，看输出里有没有收到手指数据。

**网页里没有声音。**
音频由浏览器播放。先在网页里导入音频，再用网页的播放器点播放。录制时的节拍也以浏览器播放的时间为准。

**导出的谱面整体偏早或偏晚。**
这是设备或浏览器的固定延迟。录制后点「自动校准」，或者手动调整「采样补偿」：数值为正时音符往后移，为负时往前移。

**提示端口 9000 或 8765 被占用。**
`run.bat` 每次启动都会尝试清理旧进程。手动启动时可以用 `netstat -ano | findstr :9000` 找到占用者，再用 `taskkill /f /pid 进程号` 结束它。

**还有 macOS 版本吗？**
本仓库只提供 Windows 版本。Mac 版本请参考原项目 [MiGuo2787/TouchBridge-RPE](https://github.com/MiGuo2787/TouchBridge-RPE)。

## 已知限制

- 只支持 Windows；旧的 macOS 版本已移除。
- 只支持精确式触控板。老式私有驱动的触控板、部分外接设备无法使用。
- 某些设备的手指抬起信号不完整，可能留下手指状态；点「清空」可以手动恢复。
- 在网页里改 OSC 端口后，需要重启后端才会生效。
- 导出一次只覆盖一个难度。
- 少数触控板驱动不会立即响应手势设置的变更，可能需要注销并重新登录才会生效；退出录制后设置仍会写回原位。
- 如果 `ESC` 或 `Alt+Enter` 已被其它软件全局占用，专注模式的快捷键会注册失败（采集器消息区会提示），不影响录制本身。
- 采集器没有代码签名，Windows SmartScreen 可能提示「未知发布者」，选择「仍要运行」即可。

## 你的音乐和数据

音频通过浏览器在本机播放。采集器只向本机的 `127.0.0.1:9000` 发送消息，网页和后端的访问也限制在本机。程序不收集、不上传任何音频或谱面数据。

## 遇到问题

先对照上面的常见问题。仍然解决不了，请到 GitHub Issues 反馈，并附上：Windows 版本、触控板型号、采集器窗口显示的状态文字，以及 `--diagnose` 生成的临时文件内容。反馈是公开的，方便其他人遇到同样问题时查到。
